# HandWrite — свой почерк для любого текста (0.1.0)

Офлайн-приложение для Android: вы фотографируете свой почерк, приложение строит из него
рукописный шрифт и верстает любой текст «от руки» в PDF формата A5.

Всё считается **на телефоне, на CPU**: маленькая свёрточная сеть (93.9 КиБ, int8) + классическое
зрение. Ничего не отправляется в сеть, разрешений на интернет у приложения нет.

## Что уже работает

| | |
|---|---|
| Ввод | 1–5 фото из галереи (`ACTION_OPEN_DOCUMENT`, без доступа ко всей галерее) |
| Распознавание | сегментация букв → эмбеддинг CNN → банк эталонов из 5 bundled-шрифтов, 43/43 на тестовом листе, ~9 мс/буква |
| Шрифт | атлас букв; каждая буква — **векторная траектория пера** с профилем толщины (скелет Zhang-Suen → обход жадным TSP), несколько вариантов, лигатуры из своих фото |
| Вёрстка | A5, переносы, абзацный отступ, «нажим» (толщина), наклон, дрожание, соединения букв |
| PDF | свой минимальный PDF-writer (без AndroidX/библиотек), `content://` для «Поделиться»/печати |
| EN | печатные буквы без соединений (`WritingMode.ENGLISH_PRINT`) |

## Что изменилось в 0.1.0

Буквы больше не «набор фотографий»: из каждой вырезанной буквы восстанавливается **движение пера**.

| | |
|---|---|
| Скелет | каждый символ утончается до линии в один пиксель (Zhang-Suen), концы штрихов продлеваются обратно до края чернил — иначе соединения не достают до соседа |
| Порядок штрихов | скелет превращается в граф, обход — модифицированный жадный TSP: продолжение идёт в ближайший свободный конец с учётом направления движения, пересечения проходятся насквозь, а не разрываются |
| Вектор + толщина | траектория сглаживается и превращается в полилинию с **профилем толщины** из distance transform (ширина = 2×радиус); в PDF это залитая «лента», а не контур |
| Несколько вариантов | до 6 вариантов каждой буквы, выбираются хешем позиции в строке — эффект «штампованных копий» убран |
| Соединения | конец пера одной буквы продолжается в начало пера следующей |
| Лигатуры | если на фото две буквы написаны слитно (один связанный кроп), он разрезается на две буквы **и** запоминается как лигатура: «нт» рисуется вашей собственной «нт», а не склейкой двух букв. Хранится в файле атласа (codec v3) |
| Метрики | высота и положение каждой буквы нормируются по x-height строки (а не страницы): база больше не «прыгает» |

Проверки: 11 unit-тестов на конвейер пера и нормализацию (`java -cp ... TestRunnerKt`, и `./gradlew test` в CI).

## Что изменилось в 0.0.2 (по отчёту с реального устройства)

| Проблема в 0.0.1 | Что сделано |
|---|---|
| «Буквы идут боком» (верх влево, низ вправо) | знак наклона исправлен: положительный угол теперь наклоняет вправо, у печатных режимов наклон 0 |
| Фото с телефона приходили повёрнутыми | применяется EXIF-ориентация (6 из 8 фото — «на боку») |
| «Соединения не реализованы» | соединение идёт по **траектории пера**: скелет буквы (Zhang-Suen) → магистраль движения → точка и вектор выхода одной буквы продолжаются в точку и вектор входа следующей, с опорой на базовую линию |
| Слитное письмо «размазано» | межбуквенный интервал был отрицательным (буквы наезжали друг на друга) |
| «Не распознаны английские буквы» | язык определяется **по слову**, а не по режиму: английское слово учится как английское и в русском режиме |
| Тетрадь в клетку: вместо букв — сетка | чернила выделяются **по цвету**: `(B−G) − локальный фон` — сетка, стол и тени исчезают, штрих остаётся; чёрная ручка/карандаш — отдельный путь по темноте внутри листа |
| Регистр букв путался (`о` → `О`) | регистр определяется по размеру буквы относительно строки, добавлено голосование среди похожих кропов (`LetterConsensus`) |
| Мусор в атласе портил шрифт | порог приёма поднят: неверная буква хуже отсутствующей, спорные уходят в «Уточнить» |

## Быстрый старт

```bash
bash tools/provision.sh          # JDK 17 + Android SDK 34 + kotlinc + python deps (один раз)
bash tools/build_apk.sh          # -> build/apk/handwrite-0.1.0.apk

./gradlew assembleRelease        # то же самое обычным Gradle (нужен доступ к dl.google.com)
./gradlew test                   # unit-тесты
```

Версия и applicationId живут в одном месте — `app/build.gradle.kts`; `tools/build_apk.sh` читает
их оттуда, поэтому ручная сборка и Gradle-сборка не расходятся.

APK подписывается стабильным ключом `keystore/handwrite-release.jks` (alias `handwrite`,
пароль `handwrite2026`), поэтому новые версии ставятся поверх старых. **Для F-Droid ключ не нужен:**
магазин собирает и подписывает сам, а релизные APK на GitHub Actions собираются с
`HANDWRITE_KS_PASS` / `HANDWRITE_KS_ALIAS` из секретов репозитория.

Установка: `adb install -r build/apk/handwrite-0.1.0.apk` (или открыть файл на телефоне,
разрешив установку из неизвестных источников).

## F-Droid

- Репозиторий собирается **Gradle’ом** (wrapper 8.10.2, AGP 8.7.3, Kotlin 2.0.21), `./gradlew assembleRelease`.
- Зависимостей нет вообще: ни AndroidX, ни сторонних библиотек — только Kotlin stdlib. Поэтому
  сборка воспроизводима и не тянет несвободных компонентов.
- Разрешений нет ни одного (фото выбираются через `ACTION_OPEN_DOCUMENT`); INTERNET отсутствует.
- `versionCode`/`versionName` — в `app/build.gradle.kts`; метаданные магазина — в `fastlane/metadata/android/{en-US,ru-RU}`.
- CI: `.github/workflows/build.yml` собирает APK на каждый тег `v*` и прикладывает его к релизу.
  Обновление в F-Droid: `AutoUpdateMode: Version`, `UpdateCheckMode: Tags`.

## Как получить хороший результат

1. **Свои записи — основной путь.** «Мой почерк» → «Собрать шрифт из фотографий» → 1–5 страниц
   конспекта. Из одной страницы обычно выходит 30–45 разных букв. Буквы, в которых сеть не
   уверена, попадают в «Уточнить N» и размечаются одним нажатием.
   Чем крупнее почерк на фото (поле буквы ~70 px и больше) и контрастнее ручка, тем точнее
   распознавание: мелкий слитный текст читается хуже, потому что буквы соединяются чернилами.
2. **Лист-шаблон — необязательный бонус.** «Мой почерк» → «Открыть лист-шаблон для печати».
   Напишите алфавит и цифры по одной букве в клетке, сфотографируйте лист: приложение узнаёт
   такую страницу само (по числу букв в строках) и подписывает буквы по порядку, а не по
   догадке сети. Это самый быстрый способ получить сразу все 33 буквы.
3. Экспорт: «Экспорт PDF (A5)» → «Поделиться».

## Устройство

```
app/src/main/kotlin/com/handwrite/
  core/font/         парсер TrueType (glyf/loca/cmap/kern/GSUB-заглушка), пути глифов
  core/handwriting/  сегментация (InkSegmenter), CNN (HandwriteModel), эталоны (GlyphRecognizer),
                     атлас + векторизация (GlyphAtlas/TileVectorizer), выравнивание листа
                     (AlphabetAligner), растеризация тайлов (TileRasterizer)
  core/layout/       вёрстка строк/страниц, соединения букв (HandLayout)
  core/pdf/          PDF writer + композитор страницы
  app/               Activity, UI, загрузка фото, кодеки атласа, экспорт
tools/vision/        обучение и экспорт сети (PyTorch), генератор тестовых фото, eval
tools/dev/           harness'ы: рендер PDF из фото, дампы тайлов/кропов, замеры точности
tools/build_apk.sh   сборка без Gradle: kotlinc → d8 → aapt2 → zipalign → apksigner
```

### Сеть

`GlyphNet`: 4 свёрточных блока (3×3, stride 2) → global average pool → linear 128 → L2.
Экспорт в свой бинарный формат: int8 веса + float-масштабы, batch-norm свёрнут. Инференс —
`HandwriteModel.kt`, ~91 тыс. MAC на тайл.

Обучение: 40 тыс. синтетических образцов из 18 рукописных шрифтов с аугментацией
(наклон, поворот, эластика, толщина штриха, блюр, шум, тон бумаги), ArcFace-голова.
Валидация 1-NN: 59.8 % top-1 внутри шрифтов, 64 % cross-font top-1 / 87 % top-3 на 663 эталонах.

## Ограничения 0.0.1

- Сегментация **связного** текста на фото — слабое место: буквы соединяются чернилами,
  разрезание по профилю работает только на достаточно крупном почерке. План — см. `ROADMAP.md`.
- Нет ручной обрезки/поворота фото: снимок должен быть ровным и с контрастной ручкой.
- Заглавные буквы получаются увеличением строчных (как в реальном почерке), отдельные
  прописные формы не поддерживаются.
- Кириллица/латиница: буквы, которых нет в атласе, рисуются выбранным встроенным шрифтом.
- Толщина штриха регулируется нажимом/прозрачностью; отдельного «утолщения» контура нет.

Планы на следующие версии (в т.ч. применение моделей до 3B для автодозаполнения «Уточнить») —
в [ROADMAP.md](ROADMAP.md).
