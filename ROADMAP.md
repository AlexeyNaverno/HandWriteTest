# Дальше (после 0.0.2)

0.0.1 и 0.0.2 — этапы проверки на реальном устройстве («фото записей → свой шрифт → PDF A5»).
В 0.0.2 закрыты наклон, соединения и английские буквы (см. README), но распознавание
**слитного** почерка по-прежнему главный предел качества.

## 0. Offline → online: полный порядок штрихов (следующий шаг после 0.0.2)

В 0.0.2 из статичной картинки восстанавливается **траектория движения пера** (`PenPath`):
скелет Zhang-Suen → магистраль через перекрёстки → вход/выход пера, и именно эти точки и
векторы используются для соединений. Чего в этой схеме ещё нет — полного порядка штрихов
(буква, написанная в несколько отрывов, повторные обводки, точки «й»).

Как это делают в литературе и что из этого реально поставить на телефон:

- **SORT (Sub-strokes ORdering Transformer)** и «order field»-подходы — предсказывают порядок
  фрагментов скелета и моменты отрыва пера. Небольшая модель (2–6 M параметров, int8) на CPU
  даёт полный online-вид буквы; учить можно на синтетике из bundled-шрифтов + Hershey-порядка.
- **InkSight (Google Research)** — ViT + mT5 восстанавливает цифровые чернила из фото.
  Слишком крупно для «на телефоне и офлайн» в базовом APK, но это готовый ориентир и источник
  данных для дистилляции в маленькую модель.
- **InkML / Hershey** как формат хранения порядка штрихов и как источник supervision.

Практический путь: собрать пары «фото строки → порядок штрихов» на синтетике (рендер шрифтов
с известным порядком) и обучить 2–4 M трансформер поверх скелета. Это даёт и «письмо от руки
по-настоящему» (анимация), и лучшие соединения для сложных почерков.

## 0.1. Распознавание слитного текста (в 0.0.2 всё ещё слабое место)

Сейчас на реальных фото курсива сегментация даёт корректные кропы, но классификатор
(64-мерный эмбеддинг CNN + банк эталонов) путает похожие буквы: на связном русском курсиве
top-1 заметно ниже, чем на печатном листе (43/43). Проверено экспериментально
(`tools/dev/MatchTest.kt`): прямое сравнение форм (NCC) и эмбеддинг ошибаются *по-разному* —
их объединение и контекст слова дают основной запас точности.

- **Гибридный скоринг** эмбеддинг + NCC + геометрия (дёшево, без новых моделей).
- **Контекст слова**: маленькая char-LM/CTC-модель поверх строки, а не буква по букве.
- **PaddleOCR** (open-source, ru/en, боксы) как офлайн-модуль для сложных страниц, если
  размер APK перестанет быть ограничением.

## 1. Сегментация связного текста (главное узкое место)

Сейчас буквы в слитном письме режутся по проекционному профилю; на мелком почерке чернила
соседних букв соединяются, и точность падает. Варианты, от простого к сложному:

- **Лучше классическая CV**: ватершед по расстоянию до фона, «разрезание» по скелету в точках
  ветвления, согласованность ширин по строке. Ожидаемо +10–15 % к числу корректных кропов.
- **CTC-модель строки** (CRNN на синтетике, ~0.5–1.5 M параметров, int8, CPU): читает строку
  целиком и сама выдаёт разбиение — снимает необходимость резать буквы заранее.
  Даёт и позиции для обучения атласа (выравнивание по attention/CTC-пикам).
- **Дообучение на данных пользователя**: «Уточнить» уже собирает пары «кроп → буква».
  Их можно копить локально и подстраивать последний слой (fine-tune на устройстве, ~секунды).

## 2. Более крупные модели до 3B — точечно, не для каждого тайла

Крупная модель на телефоне для **каждой** буквы не нужна и не пройдёт по CPU/батарее
(3B int4 ≈ 1.5–2 ГБ и сотни мс на токен). Разумные точки применения:

- **Автодозаполнение «Уточнить»** (то, что просили): небольшая LLM/VLM (0.5–3B) видит строку
  или страницу целиком и предлагает буквы для нераспознанных кропов с учётом языка —
  «правдоподобное слово» вместо одиночной буквы. Запуск по кнопке, батчем на страницу,
  с явным согласием пользователя (модель скачивается отдельно, 300 МБ–2 ГБ).
- **Рукописный OCR «с чистого листа»** (без шаблонного банка) для сложных почерков.
- **Диктовка/переписывание текста** (LLM 1–3B) — уже не про шрифт, отдельная функция.

Технически: llama.cpp / MLC-LLM с CPU-бэкендом и int4-квантованием, отдельный модуль
загрузки моделей, офлайн, без сетевых разрешений в основном APK.

## 3. Мелкие улучшения шрифта

- Отдельные прописные формы (сейчас заглавные — увеличенные строчные).
- Толщина штриха через морфологию контура (сейчас — только нажим/прозрачность).
- Больше вариантов букв из одной страницы (кластеризация кропов одной буквы).
- Экспорт шрифта в TTF (переменный `wght`) для использования вне приложения.
- Обрезка/поворот фото, авто-выравнивание страницы.

## 4. Релизная инфраструктура

- Версионирование по semver, журнал изменений, канал для тестеров (GitHub Releases).
